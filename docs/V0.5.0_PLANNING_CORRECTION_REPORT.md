| 8 | `knowledge` was listed as a provider. | Removed. `knowledge` is a strategy, not a provider. The provider for the knowledge strategy is `filesystem`. The `provider` enum in result/trace/metrics is restricted to `ripgrep | git_grep | filesystem | null`. |
| 9 | The result `mode` was an enum (`plan` or `execute`). | Changed to `const: "execute"`. The v0.4.0 plan-only output is unchanged. |
| 10 | Reason codes were strings without schema validation. | Created `contracts/retrieval-execution-reason-codes.schema.json` (frozen catalogue). Result, trace, and metrics reference this catalogue via `$ref`. Arbitrary strings are rejected. |
| 11 | `result_count` was loosely defined. | Made it explicit: `result_count = items.length`, bounded by `result_budget`. `raw_result_count` is preserved separately. |
| 12 | Trace and metrics could default to writing. | They are now opt-in via `--TracePath`, `--Metrics`, or `--WriteMetrics`. Default: not written. When written, they go outside the project, under the user's opencode config dir. |
| 13 | Progressive disclosure had no explicit continuation mechanism. | The result items now carry `preview_token` when `preview` is withheld. The expansion runs without repeating the wide search. |
| 14 | The benchmark was self-invented with placeholder X/Y values. | Replaced with a real, reproducible benchmark. # FINAL CONTRACT CLOSURE

The previous planning pass was rejected on multiple points. The
final contract closure addresses all of them. The closing pass
introduces the following constraints; the implementation wave must
satisfy them.

## 9.1. Contract split (v0.4.0 plan vs v0.5.0 execution plan)

The v0.5.0 release treats the v0.4.0 plan output and the v0.5.0
execution plan as **two separate contracts**:

- `retrieval-plan-base.schema.json` — v0.4.0 plan shape.
  `additionalProperties: true` (permissive). v0.4.0 plan output
  validates against this only.
- `retrieval-execution-plan.schema.json` — strict v0.5.0 plan.
  Required: `schema_version`, `mode` (const `"execute"`), `execution`
  (with required `estimated_calls`, `budget_enforcement`,
  `progressive_disclosure`, `preflight`, `repositories_searched`),
  `adapter_signature` (sha256 64 hex). `additionalProperties: false`.

The result's `plan` field is a `$ref` to the strict execution-plan.
v0.4.0 plans never appear in a result.

## 9.2. Logical adapter calls vs provider process invocations

The hard cap of 3 applies to **logical** adapter calls over the
multi-repo scope, not to internal processes. A single logical call
spawns one process per repo. The contracts use:

- `logical_adapter_calls` (renamed from `call_count`).
- `provider_process_invocations` (new).
- `focused_read_calls` (new).
- `focused_read_chars` (new).
- `fallback_count`.

Invariants:
- `logical_adapter_calls <= call_budget` (max 3).
- `fallback_count <= logical_adapter_calls`.
- `provider_process_invocations >= logical_adapter_calls`.

The old `call_count + fallback_count` sum rule is removed.

## 9.3. `executeBatch(plans, options)` + safe CLI surface

A new `executeBatch(plans, options)` runs multiple queries in one
process so the in-process equivalence cache can dedupe. The safe CLI
surface is `-BatchInput <json>` or stdin JSON. **No new public command
is introduced.**

Independent wrapper invocations do NOT share the cache. The cache is
strictly per-process.

## 9.4. Stateless progressive disclosure

Progressive disclosure is stateless. The `preview_token` is valid
only within the same batch. Expansion revalidates `scope_fingerprint`,
`allowed_root_check`, and `deny_glob_check`. Always counted as
`focused_read_calls` and `focused_read_chars`, never free.

## 9.5. Equivalence cache disabled on dirty worktree

The cache is disabled when any repository has `dirty_worktree=true`.
The reason code `CACHE_DISABLED_DIRTY_WORKTREE` is emitted. The
benchmark test demonstrates two content changes with `dirty=true`
and verifies the fingerprint behaviour.

## 9.6. `scope_fingerprint` in repository-state, `adapter_signature` in execution-plan

The `repository-state` contract carries `scope_fingerprint`
(composite of per-repo fingerprints) and no longer carries
`adapter_signature`. The `adapter_signature` is computed in
`retrieval-execution-plan` as
`sha256(scope_fingerprint + strategy + provider + normalized_query)`.

## 9.7. Exact fallback default

By default, execute mode reserves 1 primary call + 1 fallback call
within the hard cap of 3. The user can override with
`--MaxFallbacks 0` to reduce to a single call. The project-owned
policy is not modified. The plan-only v0.4.0 output is not modified.

## 9.8. Trace / metrics path restriction

`-TracePath`, `-WriteTrace`, `-WriteMetrics` must be validated via
`Resolve-Path` against the global runtime's `retrieval/` directory
(`TRUSTED_TRACE_DIR`). Paths inside the project are rejected
(`TRACE_PATH_REJECTED`, `METRICS_PATH_REJECTED`).

## 9.9. Deterministic, versioned token estimator

The result and metrics contracts require `token_estimator_version`.
The same version is used for baseline and result. The estimator is
deterministic and versioned.

## 9.10. Synthetic qs/sell fixture + provisional baseline

The qs/sell fixture at `tests/fixtures/qs-sell/` is synthetic but
faithful. It contains `SellController`, `SellService`, `Sell`,
`SellDetail`, and the endpoint literal `qs/sell`. The pilot
telemetry is **provisional / synthetic** with `provenance`,
`measurement_method`, `source_trace`, `repository_fingerprints`,
`token_estimator`, and `null` placeholder values. The savings
percentages are reserved for Phase 7 release gates.

The `tests/fixtures/qs-sell/project-manifest.json` is a valid
`project-manifest.schema.json` with `repositories[].repository_id`
and `repositories[].path` (relative POSIX). The benchmark scope
is resolved from the manifest, not from hardcoded `REPO_IDS`.

The benchmark creates deterministic git repos with fixed branch,
author date, and committer date.

## 9.11. Tests that fail (positive gates)

The contract tests fail on:
- Execution-plan without the `mode`, `execution`, `adapter_signature` addendum.
- Cache hit between separate processes.
- Stable signature incorrectly claimed on changing dirty worktree.
- Invalid fixture manifest.
- Double-count of fallback (sum of `logical_adapter_calls` + `fallback_count`).
- Expansion not measured (`focused_read_calls` / `focused_read_chars`).
- Trace path not allowed (inside the project).
- Benchmark falsely labeled as "real executed".

## 9.12. Scratch stubs removed

The scratch stubs `test-data-ref.mjs`, `test-unevaluated.mjs`, and
`retrieval-execution-contracts-sanity.mjs` are kept outside test
discovery (no `.test.mjs` suffix) and reduced to no-op / removed
content. The implementation wave may delete them.
